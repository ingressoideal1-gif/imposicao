## Visão Geral do Sistema

O **Ideal Imposition** é um sistema web para imposição gráfica de PDFs e ingressos com VDP (Variable Data Printing). Permite:

- Impor múltiplas cópias de artes em folhas de impressão (A4, SRA3, etc.)
- Numerar ingressos sequencialmente, com QR Code, código de barras, texto variável
- Schemas: `sequential`, `cut_stack`, `step_repeat`, `pdf_multiple`, `multi_artes`
- Modo frente e verso (duplex)
- Rotação de células na folha
- Upload de CSV para personalização por linha

## Bug Fix — PDF em Branco (geral)

### Problema
PDFs gerados pela imposição ficavam em branco (sem arte) em ambientes Linux (Render/nuvem), mas funcionavam localmente no Windows.

### Causa Raiz
**XObject encadeado** no PyMuPDF. O fluxo gerava uma cadeia dupla de referências:

```
out_page → temp_doc (XObject ref) → doc_base (XObject ref) ← quebrava no Linux
```

O PyMuPDF em versões Linux não resolvia corretamente a cadeia dupla de XObjects ao serializar o documento final.

### Solução (`engine.py` — linhas ~621 e ~748)

**Antes (bugado):**
```python
# Renderizava direto de temp_doc que tem XObject não resolvido
out_page_front.show_pdf_page(
    fitz.Rect(cell_x0, cell_y0, cell_x1, cell_y1),
    temp_doc, 0,
    keep_proportion=True,
    rotate=cell_rotation,
    clip=temp_page.rect
)
temp_doc.close()
```

**Depois (corrigido):**
```python
# Materializar temp_doc para bytes resolve todos os XObjects
_temp_bytes = temp_doc.tobytes(garbage=3, deflate=True)
temp_doc.close()
_temp_doc_m = fitz.open("pdf", _temp_bytes)
out_page_front.show_pdf_page(
    fitz.Rect(cell_x0, cell_y0, cell_x1, cell_y1),
    _temp_doc_m, 0,
    keep_proportion=False,    # mesmo aspect ratio → sem letterboxing
    rotate=cell_rotation,
    clip=_temp_doc_m[0].rect
)
_temp_doc_m.close()
```

A mesma correção foi aplicada na renderização do **verso** (duplex).

> **Nota:** `keep_proportion=False` foi usado porque `temp_page` e a célula final têm exatamente as mesmas dimensões, então não há necessidade de manter proporção (evita letterboxing inesperado).

## Bug Fix — Multi-artes sem imagem

### Problema
Na regra `multi_artes`, o PDF era gerado **sem a imagem de fundo** das artes. Isso acontecia de forma intermitente — funcionava logo após o upload, mas falhava após recarregar a página.

### Causa Raiz

O `rawFile` é um objeto `File` do browser — **ele não persiste entre sessões ou recargas de página**.

| Situação | `rawFile` | `pdf_url` | Resultado |
|---|---|---|---|
| Upload feito na sessão atual | ✅ presente | `"local_file"` | ✅ Funciona |
| Página recarregada / modelo carregado | ❌ `null` | `"local_file"` | ❌ Arte não enviada |

**Fluxo completo do problema:**
1. Usuário faz upload da arte → `rawFile` guardado em memória, `pdf_url = "local_file"`
2. Usuário salva modelo → Supabase armazena `pdf_url = "local_file"`, mas `rawFile` não é salvo
3. Usuário recarrega a página e carrega o modelo → `pdf_url = "local_file"` mas `rawFile = null`
4. Validação antiga só checava `if (!pdf_url)` → `"local_file"` é truthy → **passa sem erro**
5. `formData` não inclui o arquivo (sem `rawFile`) → backend recebe 0 arquivos de arte
6. `ma_files_map` fica vazio → `local_path` nunca é setado na arte
7. Engine recebe `art_doc = None` → célula fica em branco (sem arte de fundo)

### Solução

#### Frontend (`script.js`)

**1. Validação corrigida (antes de gerar a imposição):**
```javascript
// Antes:
if (!state.impMultiArtes[i].pdf_url) {
    return toast(`Por favor, faça o upload do PDF para a Arte ${i + 1}.`, 'error');
}

// Depois:
if (!state.impMultiArtes[i].pdf_url ||
    (state.impMultiArtes[i].pdf_url === 'local_file' && !state.impMultiArtes[i].rawFile)) {
    return toast(`Arte ${i + 1}: faça o upload do PDF da arte (necessário a cada sessão).`, 'error');
}
```

**2. Botão de upload — estilo indicativo:**
```javascript
// Antes: apenas verificava pdf_url
class="btn btn-sm ${a.pdf_url ? 'btn-outline' : 'btn-primary'}"

// Depois: verifica se rawFile está presente quando necessário
class="btn btn-sm ${(a.pdf_url && (a.pdf_url !== 'local_file' || a.rawFile)) ? 'btn-outline' : 'btn-primary'}"
```

**3. Texto do botão com aviso:**
```javascript
// Antes:
${a.pdf_name ? '📄 ' + a.pdf_name : '📁 Escolher PDF'}

// Depois:
${a.rawFile ? '📄 ' + a.pdf_name : (a.pdf_url === 'local_file' ? '⚠️ Reenviar: ' + a.pdf_name : '📁 Escolher PDF')}
```

**4. Aviso visual abaixo do botão:**
```html
${a.pdf_url === 'local_file' && !a.rawFile
  ? `<span style="color:#f59e0b;font-size:0.7rem;">⚠️ Faça o upload novamente</span>`
  : ''}
```

#### Backend (`app.py` e `local_print_agent.py`)

Logs de diagnóstico adicionados para rastrear o mapeamento de arquivos nos logs do Render:
```python
# Diagnóstico multi_artes (Render logs)
print(f"[multi_artes] Arquivos recebidos ({len(ma_files_map)}): {list(ma_files_map.keys())}")
for _ma in multi_artes_list:
    _pn = _ma.get("pdf_name"); _lp = _ma.get("local_path")
    print(f"[multi_artes] Arte pdf_name={_pn!r} -> local_path={_lp is not None}")
```

### Como o mapeamento de arquivos funciona (backend)

```python
# 1. Receber arquivos enviados via FormData
multi_artes_files: list[UploadFile] = File(default=[])

# 2. Salvar cada arquivo em temp e mapear pelo nome
ma_files_map = {}
for ma_file in multi_artes_files:
    if ma_file and ma_file.filename:
        ext = os.path.splitext(ma_file.filename)[1].lower() or ".pdf"
        with tempfile.NamedTemporaryFile(delete=False, suffix=ext) as tmp_in:
            shutil.copyfileobj(ma_file.file, tmp_in)
            ma_files_map[ma_file.filename] = tmp_in.name

# 3. Setar local_path em cada arte pelo pdf_name
for ma in multi_artes_list:
    pdf_name = ma.get("pdf_name")
    if pdf_name and pdf_name in ma_files_map:
        ma["local_path"] = ma_files_map[pdf_name]
```

> **Nota importante:** `pdf_name` no payload JSON deve corresponder exatamente ao `filename` do arquivo no FormData. Ambos são derivados de `rawFile.name` (o nome do arquivo selecionado pelo usuário). Nomes com caracteres especiais podem causar mismatch em alguns navegadores/sistemas.

### Correção aplicada no instalador (erro `IPersistFile 0x80070005`)

O erro `0x80070005` (Access Denied) ocorria porque o instalador tentava escrever em diretórios protegidos (`Program Files`). A correção foi usar diretórios do usuário atual:

**`installer.iss` — antes (bloqueado pelo UAC):**
```ini
DefaultDirName={commonpf}\IdealImposition   ; ← Program Files - negado!
DefaultGroupName=Ideal Imposition            ; ← Start Menu global - negado!
```

**`installer.iss` — depois (sem necessidade de admin):**
```ini
DefaultDirName={localappdata}\IdealImposition  ; ← AppData\Local do usuário
DefaultGroupName=Ideal Imposition
PrivilegesRequired=lowest                       ; ← não pede UAC
```

## Arquitetura do Engine (`engine.py`)

### Fluxo de renderização por célula

```
Para cada célula na folha:
  ┌─────────────────────────────────────────────────────┐
  │ 1. Criar temp_doc (fitz.open()) — página item_w×item_h │
  │                                                       │
  │ 2. Inserir arte base na temp_page                     │
  │    temp_page.show_pdf_page(rect_art, doc_base, ...)  │
  │                                                       │
  │ 3. Renderizar elementos VDP na temp_page              │
  │    (TEXT, QR, BARCODE, SVG, PDF)                     │
  │                                                       │
  │ 4. **MATERIALIZAR** temp_doc → bytes → reabrir       │
  │    _temp_bytes = temp_doc.tobytes(garbage=3)          │
  │    _temp_doc_m = fitz.open("pdf", _temp_bytes)       │
  │                                                       │
  │ 5. Copiar célula materializada para a folha final     │
  │    out_page.show_pdf_page(cell_rect, _temp_doc_m, 0) │
  └─────────────────────────────────────────────────────┘
```

### Schemas disponíveis

| Schema | Descrição |
|--------|-----------|
| `sequential` | Itens em ordem: folha 1 = itens 1-N, folha 2 = itens N+1-2N... |
| `cut_stack` | Empilhamento cortado: coluna 1 = série A, coluna 2 = série B... |
| `step_repeat` | Todas as células com o mesmo item (repetição total) |
| `pdf_multiple` | Cada página do PDF em uma célula diferente |
| `multi_artes` | Artes distintas com quantidades individuais |
